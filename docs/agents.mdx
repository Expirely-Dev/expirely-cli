title: AI agents and CI
description: JSON outside a terminal, stable codes and exit codes a program can act on.

expirely is built to be run by a program as much as by a person. An agent or a pipeline needs no flag to get machine-readable output, and every outcome has a code that does not change.

## JSON without asking

When stdout is not a terminal, such as a pipe, a file or a CI log, expirely prints the JSON report. `--json` forces it in a terminal too.

```sh
expirely tls -f targets.txt | jq '.summary'
```

```json
{ "error": 0, "expired": 1, "expiring": 0, "ok": 3, "total": 4 }
```

Every field is described in [Output](/reference/output). A value that could not be read is `null`, never zero or a default date. The report starts with `summary`, `filter`, `matched`, `truncated` and `unreadable`, so an agent that reads only the first lines of a long scan still sees the counts and whether it has every result, and it leaves each certificate chain out unless `--details` asks for it.

## Show only what needs attention

One result is about 1 KB of JSON, and agent harnesses cut long output: Claude Code shows about 10,000 characters of a command that exits non-zero, from its start and end, so a scan of a few dozen targets that finds an expiring certificate arrives cut. A declared agent therefore gets only the results that need attention, `expired`, `expiring` and `error`, unless it passes `--status`; `summary` still counts the `ok` ones, and `--status all` shows them. Nothing else changes by default, and no result limit applies unless asked for:

```sh
expirely tls -f targets.txt --fields status,days_left,expires_at --limit 20
```

`--fields` and `--limit` are in [Show less](/reference/output#show-less). The exit code always covers every result.

## Agents on a terminal

Some agents run commands under a pseudo-terminal, where expirely would otherwise draw a spinner and color. expirely reads the environment, stops at the first match, and adapts:

| Variable                                                      | Agent      | What changes                    |
| ------------------------------------------------------------- | ---------- | ------------------------------- |
| `EXPIRELY_AGENT=1` or `true`                                  | declared   | JSON, no color, no spinner      |
| `EXPIRELY_AGENT=0` or `false`                                 | a person   | detection is off                |
| `AI_AGENT=<name>`, then `AGENT=<name>`                        | declared   | JSON, no color, no spinner      |
| `CODEX_SANDBOX`, `CODEX_CI`, `CODEX_THREAD_ID`                | declared   | JSON, no color, no spinner      |
| `GEMINI_CLI`, `CURSOR_AGENT`, `COPILOT_CLI`, `OPENCODE`, `CLAUDE_CODE_CHILD_SESSION` | detected | no color, no spinner |
| `CLAUDECODE=1`, only when stdout is not a terminal            | detected   | no color, no spinner            |

A detected agent that makes a usage error also gets the whole help, in the `usage` field of the error envelope or after the message in text, since it cannot glance at `--help` the way a person does. A declared agent said what it is, so it gets JSON even on a terminal. `CLAUDECODE` alone is not enough on a terminal, because IDE terminals that people type in set it too. An explicit `--json` or `--json=false` wins over all of this.

## Decide on the exit code

| Exit | What to do                                                    |
| ---- | ------------------------------------------------------------- |
| `0`  | Nothing: every target is `ok`                                 |
| `1`  | Renew: a certificate is `expired` or `expiring`               |
| `2`  | Fix the command: a flag, a target or a `--file` is wrong      |
| `3`  | Look at the network: a target could not be read               |
| `130`| Run it again: it was stopped and printed no results           |

When a scan has both, `1` wins over `3`.

## Match on codes, not messages

A command error is one JSON line on stderr. A target that could not be read carries a `code` in its `error` field too, and a chain that does not verify names why in `trust_issue`:

```json
{"error":{"code":"invalid_target","message":"invalid target \"http://example.com\": scheme \"http\" does not use TLS; only https:// does","remediation":"A target is host, host:port, [ipv6]:port or https://host/path; the port defaults to 443."}}
```

Every error also carries a `remediation`: what resolves it, stated as a fact about the tool rather than an instruction, so an agent harness does not read it as prompt injection, and never repeating what was typed. Messages, reasons and remediations are for people and can change. Codes and `trust_issue` values are never renamed or reused; they are listed in [Error codes](/reference/error-codes) and [Output](/reference/output).

## Safe to run

expirely only reads. It completes a TLS handshake and closes the connection, sends no application data and no credentials, and removes control characters from text taken from certificates before printing it in a terminal. Its progress spinners, in a scan and while `expirely tls aws` or `expirely tls gcp` reads, are drawn only when stderr is a terminal, so a program reading stderr gets errors and nothing else. The one exception is a GitHub Actions workflow, where stderr also carries the annotation commands the runner turns into annotations.
