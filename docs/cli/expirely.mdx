---
title: expirely
description: Scan TLS targets and report when their certificates expire.
---

`expirely` reads its targets from the arguments and from each `--file`, scans them, prints one result per target and exits with a code that says whether anything needs attention. The target syntax is in [Scan targets](/guides/targets).

```sh
expirely example.com api.example.com:8443
expirely -f targets.txt --warn-days 21
cat targets.txt | expirely -f - --json
expirely -f targets.txt --concurrency 64 --timeout 3s
```

| Flag                 | Description                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| `--concurrency N`    | Targets scanned at once, `1` or more. Default `16`                                                |
| `-f`, `--file PATH`  | Read targets from `PATH`, one per line; `-` reads stdin. Can be given more than once              |
| `-h`, `--help`       | Print the help as text and exit `0`                                                               |
| `--json`             | Print JSON. Also the default when stdout is not a terminal                                        |
| `--timeout DURATION` | Time each target has to connect and complete the handshake, such as `3s`. Default `10s`           |
| `--version`          | Print the version and exit `0`                                                                    |
| `--warn-days N`      | Report certificates that expire within `N` days as `expiring`, `0` or more. Default `30`          |

## Status

Each target gets one status:

| Status     | Meaning                                                    |
| ---------- | ---------------------------------------------------------- |
| `expired`  | The first certificate in the chain to expire has expired   |
| `expiring` | It expires within `--warn-days`                            |
| `ok`       | It expires later than that                                 |
| `error`    | The target could not be read                               |

The status comes from the earliest `NotAfter` in the chain the server sends, so an intermediate that expires before the leaf is reported. Trust does not change the status: an untrusted chain far from expiry is `ok`, with `trusted` false.

## Output

Results go to stdout and errors to stderr. The output is JSON when `--json` is set or stdout is not a terminal, and text otherwise. JSON keeps the order of the targets and is described in [Output](/reference/output).

The text output has one line per target, most urgent first, then the counts and how long the scan took:

```
  expired  expired.badssl.com         4,246 days ago      Apr 12 2015
  failed   localhost:1                connection refused
  ok       wrong.host.badssl.com      31 days             Dec 28 2026  wrong name

  1 expired, 1 failed, 1 ok in 622ms
```

- The status comes first: `expired`, `expiring`, `failed` or `ok`. `failed` is the `error` status of JSON.
- The default port is left out, as in `example.com`; other ports are shown.
- A chain that is not trusted says why: `self-signed`, `untrusted issuer`, `wrong name` or `not trusted`. An expired chain needs no note.
- In a terminal with color, `expired` and `failed` are red, `expiring` is yellow and `ok` is green. With `NO_COLOR` set or `TERM=dumb` the text is the same without color.
- While a scan that takes longer than 150 ms runs, stderr shows `Scanning N targets` with the count finished so far, and erases that line before the results print. It appears only when stderr is a terminal, so pipes, logs, CI and agents never see it.

Text taken from certificates and errors has its control characters removed before it reaches a terminal.

## Environment

| Variable         | Effect                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------ |
| `NO_COLOR`       | Text without color                                                                         |
| `TERM=dumb`      | Text without color and no spinner                                                          |
| `EXPIRELY_AGENT` | `1` makes expirely behave as run by an agent; `0` turns agent detection off                |
| `AI_AGENT`, `AGENT` and agent markers | Detected AI agents get no color and no spinner; declared ones get JSON. See [AI agents and CI](/agents) |

## Exit codes

`0` when every target is `ok`, `1` when a certificate is `expired` or `expiring`, `2` for a usage error and `3` when a target could not be read. `1` wins over `3`. Each code is in [Error codes](/reference/error-codes).
