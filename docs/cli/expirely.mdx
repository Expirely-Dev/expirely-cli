title: expirely
description: The commands of expirely and what they share.
---

`expirely` itself does no work: it routes to a command. With no arguments, or with `--help`, it prints its help and exits `0`.

```sh
expirely tls example.com api.example.com:8443
expirely tls -f targets.txt --warn-days 21
expirely tls aws --region all
expirely tls gcp --project acme-production
```

| Command | What it does |
| --- | --- |
| [`expirely tls`](/cli/tls) | Checks the certificates TLS endpoints serve |
| [`expirely tls aws`](/cli/tls-aws) | Lists the certificates in AWS Certificate Manager |
| [`expirely tls gcp`](/cli/tls-gcp) | Lists the certificates of a Google Cloud project |

| Flag | Description |
| --- | --- |
| `--version` | Print the version and exit `0` |
| `-h`, `--help` | Print this help and exit `0`. Each command prints its own flags with `--help` |

## Shared by every command

Every command reports the same way: the same statuses, the same [JSON report](/reference/output), the same [error codes](/reference/error-codes), and the same exit codes: `0` when every certificate is `ok`, `1` when one is `expired` or `expiring`, `2` for a usage error, `3` when something could not be read or an end date is `unknown`, and `130` when Ctrl-C stopped the run. `1` wins over `3`. The environment variables each command reads are in [expirely tls](/cli/tls#environment).

## Commands that moved

Before 0.9, `expirely TARGET...`, `expirely aws` and `expirely gcp` were the commands. They still work, and print a warning on stderr, or an annotation in GitHub Actions, that names the command to use instead:

| Before | Now |
| --- | --- |
| `expirely example.com` | `expirely tls example.com` |
| `expirely -f targets.txt` | `expirely tls -f targets.txt` |
| `expirely aws` | `expirely tls aws` |
| `expirely gcp` | `expirely tls gcp` |

The old forms stop working in expirely 1.0.
