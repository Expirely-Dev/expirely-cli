---
title: Gate CI and alert from cron
description: Fail a pipeline or raise an alert before a certificate expires.
---

expirely exits with `1` when any certificate is expired or expires within `--warn-days`, with `3` when a target could not be read, and with `0` otherwise. Any runner that stops on a non-zero exit code can use it as a gate.

## GitHub Actions

[expirely-dev/expirely-action](https://github.com/expirely-dev/expirely-action) installs a pinned expirely, checks the archive against its SHA-256 and runs it:

```yaml .github/workflows/certificates.yml
name: certificates

on:
  pull_request:
  schedule:
    - cron: "0 8 * * 1-5"

permissions: {}

jobs:
  expiry:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: expirely-dev/expirely-action@v2
        with:
          targets: |
            example.com
            api.example.com:8443
```

Inside a workflow, expirely itself adds to the run, with or without the action:

- A job summary with a table of every certificate that needs attention, most urgent first, or the one that expires first when all are ok.
- An annotation per certificate that needs attention: an error for `expired` and `error`, a warning for `expiring`. GitHub shows 10 of each kind per step, so expirely writes the most urgent 10 and a notice counting the rest.
- The step fails on exit code `1` or `3`, like any command. To report without failing, add `continue-on-error: true` to the step.

The summary and annotations cover every result, whatever `--status`, `--fields` and `--limit` show. `EXPIRELY_GITHUB=0` turns them off. Without the action, install the binary and run it like any other command:

```yaml
      - run: go install github.com/expirely-dev/expirely-cli/cmd/expirely@latest
      - run: expirely tls -f targets.txt --warn-days 21
```

Outside a terminal expirely prints JSON, so the job log carries the full report. Add `--json=false` for the text output.

## Cron

```sh
expirely tls -f /etc/expirely/targets.txt --warn-days 14 > /var/log/expirely.json
case $? in
  1) echo "a certificate expires within 14 days" | mail -s "certificates" ops@example.com ;;
  3) echo "a target could not be read" | mail -s "certificates" ops@example.com ;;
esac
```

## Pick what to act on

```sh
expirely tls --json -f targets.txt | jq -r '.results[] | select(.status == "expiring" or .status == "expired") | "\(.target) \(.days_left)"'
```
