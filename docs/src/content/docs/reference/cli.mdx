---
title: Command line
description: Every flag of expirely and how it reads targets.
---

```sh
expirely [flags] [TARGET...]
```

| Flag | Default | Meaning |
|---|---|---|
| `--concurrency N` | `16` | Targets scanned at once; 1 or more |
| `-f`, `--file PATH` | | Read targets from `PATH`, one per line; `-` reads stdin; repeatable |
| `-h`, `--help` | | Print the help as text and exit 0 |
| `--json` | off | Print JSON; also the default when stdout is not a terminal |
| `--timeout DURATION` | `10s` | Time each target has to connect and complete the handshake; positive |
| `--version` | | Print the version and exit 0 |
| `--warn-days N` | `30` | Report certificates expiring within `N` days as `expiring`; 0 or more |

`TARGET` and file syntax are described in [Scan targets](/expirely-cli/guides/targets/).

## Status

Each target gets one status:

| Status | Meaning |
|---|---|
| `expired` | The first certificate in the chain to expire has expired |
| `expiring` | It expires within `--warn-days` |
| `ok` | It expires later than that |
| `error` | The target could not be read |

The status comes from the earliest `NotAfter` in the chain the server sends, so an intermediate that expires before the leaf is reported. Trust does not change the status: an untrusted chain far from expiry is `ok`, with `trusted` false.

## Output

Results go to stdout and errors to stderr. Output is JSON when `--json` is set or stdout is not a terminal, and a table otherwise. The table lists the most urgent targets first and ends with a summary line; JSON keeps the order of the targets. Text taken from certificates and errors has its control characters removed before it reaches a terminal.
