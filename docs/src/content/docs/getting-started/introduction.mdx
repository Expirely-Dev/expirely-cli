---
title: Introduction
description: What expirely does and what it never does.
---

expirely connects to each target you give it, completes a TLS handshake, reads the certificate chain and closes the connection. It tells you which certificates are expired, which expire soon, and which targets could not be read.

```sh
$ expirely example.com expired.badssl.com self-signed.badssl.com wrong.host.badssl.com localhost:1
TARGET                      STATUS   DAYS     EXPIRES               TRUSTED  DETAIL
expired.badssl.com:443      expired  -4246    2015-04-12 23:59 UTC  no       issuer COMODO RSA Domain Validation Secure Server CA
localhost:1                 error    unknown  unknown               unknown  dial localhost:1: dial tcp [::1]:1: connect: connection refused
wrong.host.badssl.com:443   ok       31       2026-12-28 20:02 UTC  no       issuer YR1
example.com:443             ok       88       2027-02-22 23:53 UTC  yes      issuer Cloudflare TLS Issuing ECC CA 3
self-signed.badssl.com:443  ok       727      2028-11-23 21:00 UTC  no       issuer *.badssl.com

5 targets: 1 expired, 0 expiring, 1 unreadable, 3 ok
```

## What it reads

- The whole chain a server sends, leaf first. A target expires when the first certificate in its chain expires, so an intermediate that expires before the leaf is caught.
- Expired, untrusted and mismatched chains. They are read and reported, not refused.

## What it never does

- Send application data or credentials. The connection ends after the handshake.
- Handle private keys or change anything on the target.
